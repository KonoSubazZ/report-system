# 项目整体架构说明

## 1. 文档范围

本文基于 `report_en7` 当前源码、`WebContent` 资源、`docs/AGENTS.md` 约束、`docs/NOVO检测报告-通用双样本.docx` 模板和 `docs/MP242605084031-NOVO泛癌种1238检测报告280889.docx` 生成样例梳理。所有结论仅来自现有代码和文件，不补充未在项目中体现的业务假设。

## 2. 项目形态

- 项目类型：传统 Eclipse Dynamic Web Project，无 Maven/Gradle 构建文件。
- 部署形态：`WebContent` 作为 Web 根目录，`WebContent/WEB-INF/lib` 存放运行依赖 Jar，按 WAR/Tomcat 方式部署。
- 后端框架：Spring MVC 4.2.x + MyBatis 3.3 + Druid。
- 前端形态：JSP + jQuery + Pintuer/自定义 CSS，前后端不分离。
- 报告生成：Java 组装报告数据，写入临时 JSON，调用 Python `generate_report.py` 使用 `docxtpl` 渲染 Word。
- 第三方依赖：MySQL 多数据源、Redis、SMTP/IMAP 邮件、SSH/SFTP、内部 HTTP/WebService、Python 脚本。

## 4. 分层架构

### 4.1 Web 层

`web.xml` 将 `DispatcherServlet` 映射为 `/`，所有 Controller 由 `springmvc.xml` 扫描 `com.novo.report.controller` 注册。静态资源通过 `<mvc:resources>` 放行，JSP 通过 `InternalResourceViewResolver` 解析到 `/WEB-INF/jsp/{view}.jsp`。

实际登录拦截器配置在 `springmvc.xml` 中被注释，`LoginInterceptor` 类存在但未注册；因此源码层面的全局登录拦截不生效，权限主要依赖页面入口和 Controller 内部对 session user 的直接读取。

### 4.2 业务层

`applicationContext-service.xml` 扫描 `com.novo.report.service` 和 `com.novo.report.controller`。主要业务域：

- NGS 报告：`NgsReportController`、`GeneMarkerVwController`、`PyReportServiceImpl`、`ComplexMutationServiceImpl`、`ReportCrServiceImpl`。
- 位点筛选：`FilterSnpIndel/Cnv/Fusion/Chemical/Cr/Pd/Qc` 系列 Controller 和 Service。
- 样本：`SampleFileController`、`LifeController`、`SampleRetrievalController`。
- 其他报告：PCR、PD-L1、MSI、OfflineReport。
- 邮件：`NgsReportController.sendEmail`、`OfflineReportController`、`EmailUtil`、`SendEmailController`。
- 小报告：`SubReportServiceImpl`、`SubreportProducer`、`SubreportConsumer`。

### 4.3 数据层

`applicationContext-dao.xml` 配置 4 个 Druid 数据源：

- `dataSourceOne` → `com.novo.report.dao.one`
- `dataSourceTwo` → `com.novo.report.dao.two`
- `dataSourceThree` → `com.novo.report.dao.three`
- `dataSourceFour` → `com.novo.report.dao.four`

事务管理器只绑定 `dataSourceTwo`。XML 注释写明 “1、3 数据源只查询不需要事务”，但代码也存在第四数据源和第三数据源更新逻辑，需要重构时重点核验跨数据源事务边界。

### 4.4 报告模板层

报告模板以 Word docx 存放在 `WebContent/docx`。Java 根据 `ReportTemplate.template_name` 拼接模板路径：`{webRoot}/docx/{template_name}.docx`。`generate_report.py` 又可根据 `report_config.json` 的 `module_enabled` 和模板映射把输入模板替换为通用模板，例如单样本、双样本、无章版、河南肿瘤等通用模板类型。

`docs/NOVO检测报告-通用双样本.docx` 中实际包含 Jinja/docxtpl 标签，例如 `summaryOfRresults`、`reportInfo`、`BodyDrugNoComplexStr`、`ComplexDrugStr`、`hrdanalysisOfImmuneTestResults`、`gene.conf_genes.gene_tables`。`docs/MP242605084031-NOVO泛癌种1238检测报告280889.docx` 生成样例呈现了样本信息、检测项目、结果小结、肺癌相关基因汇总、体细胞变异、胚系变异、FDA/NMPA 药物、免疫、HRR、化疗、质控、基因列表、参考文献等章节。

## 5. 核心模块关系

```text
JSP 页面
  -> Controller
    -> Service / DAO
      -> MyBatis XML / Redis / SMTP / SSH / Python
        -> 数据库 / 报告文件 / 外部系统
```

NGS 报告主链路：

```text
NgsAvailableDataVw/ngsList
  -> life/lifeMain 或 iframe 页面
  -> geneMarkerVw/getGeneMarkerData 预览并匹配模块
  -> geneMarkerVw/produceReport 进入生成页
  -> ngs/createReport
  -> PyReportServiceImpl.createReport2
  -> ComplexMutationServiceImpl.matchComplexMutation
  -> ReportCrServiceImpl.handleDrugList / matchNKBVarDrug
  -> PyAnalysisReportTemplateUtil.getFreeMarker
  -> TemplateUtil2.stat_report
  -> python3 generate_report.py template.docx tempJson.json output.docx
```

## 6. 外部依赖概览

| 依赖 | 代码入口 | 用途 |
| --- | --- | --- |
| MySQL/Druid | `applicationContext-dao.xml`、各 DAO XML | 样本、报告、NKB、LIMS、新系统、二维码等数据。 |
| Redis/Jedis | `JedisUtils`、`SubreportProducer`、`SubreportConsumer` | 小报告异步队列 `subreport_generation_queue`。 |
| SMTP/IMAP | `EmailUtil`、`mail.properties`、`mail_IVD.properties` | 发送报告邮件并通过 IMAP 校验发送结果。 |
| SSH/SFTP | `RemoteShellExecutor`、`NativeRemoteShellExecutor`、`Jsch`、`SFTPUploader` | 数据上传、备份、TMB 图片、河南肿瘤文件同步。 |
| Python | `TemplateUtil2`、`generate_report.py`、`NgsReportController`、`SubreportConsumer` | docx 报告渲染、河南肿瘤导出、小报告、报告同步脚本。 |
| 内部 HTTP/WebService | `WebserviceProxyUtils`、`LimsWebserviceProxyUtils`、`YFWebserviceProxyUtils` | 状态回传、小报告 HTTP 触发、LIMS/银丰系统调用。 |

## 7. 架构结论

该项目是典型老 Java Web 单体：Controller 直接承担页面跳转、状态控制、文件处理、线程创建、外部调用等职责；Service 中存在大量模板特化分支；MyBatis SQL 同时访问 `omics`、`nkb`、`snkb`、LIMS 等多库对象；报告生成同时依赖 Java 模板对象、Python 脚本、Word 模板、外部配置和文件系统。后续重构应优先建立端到端回归样例，尤其是 NGS 报告生成、邮件发送、报告状态更新和 Python 渲染链路。
