# 项目隐藏逻辑、技术债务、重构风险点清单

## 1. 权限与会话风险

- `springmvc.xml` 中 `LoginInterceptor` 被注释，实际没有全局登录拦截。
- `LoginController` 登录成功后设置 session 永不过期：`setMaxInactiveInterval(-1)`。
- 多数 Controller 直接读取 session `user`，未统一处理未登录场景，存在空指针或绕过风险。
- 权限粒度主要由页面入口控制，后端接口缺少统一角色校验。

## 2. 硬编码路径与环境耦合

以下是代码中存在的路径/环境依赖类型，文档不记录敏感账号密码值：

- Python 包路径：`/data/soft/python3-packages`。
- Python 日志目录：`/data/soft/apache-tomcat-8.5.43/logs`。
- 小报告脚本：`/data/soft/scripts/generate_xbg.py`。
- 小报告输出根目录：`/data/soft/subreport/`。
- 河南肿瘤导出目录：`/data/soft/execl`。
- 报告同步脚本：`/home/cyc/report_url1.py`。
- TMB 图片脚本和输出目录：`/TJPROJ2/...`、`/TJPROJ11/...` 等。
- 日志工具固定目录：`LogUtils.LOG_DIR`。
- 报告输出目录由 Web 根父目录拼接 `/TESTREPORT/{platform}`。
- 模板路径固定为 Web 根下 `docx/{template_name}.docx`。

## 3. 敏感信息与配置风险

- `jdbc.properties`、`redis.properties`、`mail.properties`、`mail_IVD.properties`、`jsch.properties`、`user.properties` 含连接地址、账号、密码，应禁止进入公开文档和日志。
- 代码中存在硬编码远程主机、账号或密码的调用痕迹，重构时需统一迁移到密钥管理或环境变量，并清理历史提交。
- `GeneToRedUtils` 会打印配置中的主机、用户名、密码属性，存在泄露风险。
- `RemoteShellExecutor` 注释中保留历史 root/密码示例。

## 4. 异常处理和日志风险

- 大量接口使用 `e.printStackTrace()`，没有结构化日志、业务上下文或统一错误码。
- 多数 Ajax 更新接口异常后直接返回 `false`，前端难以区分原因。
- `GeneMarkerVwController.getGeneMarker` 捕获异常后仍返回预览 JSP，可能导致页面展示半数据。
- `CustomExceptionHandler` 只绑定 `GeneMarkerVwController`，异常响应格式为 `{errorMsg,isError}`，未做全局统一异常处理。
- `TemplateUtil2` Python 失败只打印 stderr 并返回 `null`，上层以文件名/路径缺失判断失败。
- `NgsReportController.createReport` 异常返回 `-1`，业务错误、模板错误、Python 错误被压缩为同一结果。

## 5. Python 调用风险

- `TemplateUtil2` 使用 `Runtime.exec(String[])`，未设置超时。
- 等待进程结束前没有持续消费 stdout/stderr，输出过多可能死锁。
- Python 脚本路径依赖 classpath 目录，部署结构变化会导致找不到脚本。
- `generate_report.py` 依赖服务器固定目录和同目录配置/脚本。
- `generate_report.py` 中 `report_config.json` 控制模板替换，Java 侧传入模板不一定是最终实际模板。
- Python 渲染异常跨进程回传信息弱，Java 无结构化错误对象。

## 6. 数据一致性风险

- 事务管理器只绑定 `dataSourceTwo`，跨数据源操作无全局事务。
- NGS 预览链路会写入/更新 `analysis_report`、`rp_*`、`mm_*` 表，不是纯只读。
- `PyReportServiceImpl` 在生成报告后再写 `analysis_report_store`，如果文件已生成但 DB 更新失败，会出现文件和数据库不一致。
- 邮件发送成功后异步更新状态，异步线程失败可能导致邮件已发但状态未更新。
- 河南肿瘤异步上传报告和 SQL，异常仅打印堆栈，不回滚报告生成。

## 7. 业务硬编码风险

- 癌种 ID 直接散落在代码中，如 `9256`、`2531`、`10000003`、`3590`、`263`、`4007`、`11812`、`120`、`3856`。
- 模板名字符串判断大量存在，如 `蚌埠`、`银丰`、`广附一`、`三峡`、`重医附二`、`湖南肿瘤`、`同济`、`赛福`、`晶赛`、`河南人民`、`基石`。
- 客户名字符串直接影响文件名、上传、邮件、模板数据。
- 产品名/panel 名直接影响模块、频率显示、Fusion 频率、基因标红、QC 判断。
- `ComplexMutationServiceImpl` 中共突变输出 ID 和多靶点模板判断硬编码。

## 8. 废弃和注释遗留

- `springmvc.xml` 中登录拦截器被注释。
- `LoadOcacleListener` 未在 `web.xml` 注册，但包含完整定时备份逻辑。
- `GeneMarkerVwController` 中保留多版 `saveMmApprovedDrugs` 注释实现。
- `generate_report.py` 中旧版模板匹配函数标注 deprecated。
- `PyReportServiceImpl` 中多处注释提示“不会生效吧”“暂时不用”“待升级”。
- 多个 Controller/Util 中存在 TODO 和历史 WebService/HTTP 调用注释。

## 9. 第三方依赖风险

- Redis 队列消费者随 Spring MVC 容器启动，Redis 不可用时持续重试。
- 小报告生成依赖外部 Python 脚本和 Redis 队列，失败只更新状态文案。
- 邮件发送依赖 SMTP 和 IMAP 双重成功，IMAP 地址在工具类中固定。
- SSH/SFTP 依赖远程服务器目录和账号权限。
- Webservice/HTTP 状态回传使用硬编码内部地址，异常多为打印堆栈。

## 10. 文件与并发风险

- 报告文件名由样本、客户、模板名、报告 ID 拼接，并通过 `replaceFileName` 替换非法字符；仍需注意超长文件名、同名覆盖和特殊字符。
- 报告目录由 Web 根父目录推导，部署目录变化会影响输出。
- `TemplateUtil2` 临时 JSON 使用系统临时文件，未见成功后删除逻辑。
- Python `DocxTemplate` 已改为 BytesIO 加载以降低并发污染，但 Java 侧进程调用仍无限制并发。
- 多处 `Executors.newCachedThreadPool()` 和 `new Thread()` 无统一线程池管理。

## 11. 重构优先级建议

1. 建立 NGS 报告端到端回归集：固定输入报告 ID、模板、JSON、生成 docx、关键章节文本比对。
2. 先抽离 Java→Python 调用适配层，统一超时、stdout/stderr 消费、错误码和日志。
3. 将模板名、癌种 ID、客户名、产品名分支迁移到配置表或规则表，但迁移前必须保留 1:1 快照测试。
4. 统一登录/权限拦截，并先盘点允许匿名访问的真实接口。
5. 将 `rp_*`、`mm_*` 的“预览写库”行为显式标记，避免重构时误改为只读。
6. 建立多数据源事务边界文档，禁止跨库写操作假定原子性。
7. 清理敏感信息输出、硬编码密钥和历史注释，但先用配置扫描确认生产依赖。
