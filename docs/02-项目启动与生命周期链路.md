# 项目启动与全生命周期运行链路

## 1. Tomcat 启动入口

`WebContent/WEB-INF/web.xml` 是真实启动入口：

1. 读取 welcome file：`index.jsp`。
2. 通过 `ContextLoaderListener` 加载 `classpath:spring/applicationContext-*.xml`。
3. 注册 Druid 监控 Servlet：`/druid/*`。
4. 注册 `CharacterEncodingFilter`，设置 UTF-8，匹配 `/*`。
5. 注册 Spring MVC `DispatcherServlet`，名称 `boot-report`，加载 `classpath:spring/springmvc.xml`，映射 `/`。

## 2. Spring 容器初始化

### 2.1 DAO 容器

`src/spring/applicationContext-dao.xml` 执行：

- 读取 `jdbc.properties`。
- 初始化 4 个 Druid 数据源。
- 为每个数据源创建独立 `SqlSessionFactoryBean`。
- 扫描 DAO 包：
  - `com.novo.report.dao.one`
  - `com.novo.report.dao.two`
  - `com.novo.report.dao.three`
  - `com.novo.report.dao.four`
- 数据源二加载 `mybatis-config.xml`。
- 事务管理器 `transactionManager` 只绑定 `dataSourceTwo`。
- 通过 AOP 对 `com.novo.report.service..*.*(..)` 方法按方法名前缀套用事务规则。

### 2.2 Service 容器

`src/spring/applicationContext-service.xml` 扫描：

- `com.novo.report.service`
- `com.novo.report.controller`

Controller 同时被 root 容器和 MVC 容器扫描，属于重复扫描风险点。

### 2.3 MVC 容器

`src/spring/springmvc.xml` 执行：

- 扫描 `com.novo.report.controller`。
- 启用注解驱动。
- 放行 `/css/**`、`/js/**`、`/jquery/**`、`/images/**`、`/lib/**`。
- 视图解析：`/WEB-INF/jsp/` + 逻辑视图名 + `.jsp`。
- 注册 `subreportConsumer`，`init-method="start"`，`destroy-method="stop"`。
- 配置上传组件 `CommonsMultipartResolver`，最大 100MB。
- 登录拦截器配置存在但被整段注释，实际不生效。

## 3. 启动时后台线程

`springmvc.xml` 注册 `SubreportConsumer`，容器初始化后调用 `start()`：

1. 创建线程 `Subreport-Sync-Consumer-{instanceId}`。
2. 从 Redis 队列 `subreport_generation_queue` 执行 `brpop(30, queue)`。
3. 解析 JSON 任务，读取 `task_id`、`subreport_path`。
4. 调用 Python：`python /data/soft/scripts/generate_xbg.py {taskId}`。
5. 600 秒超时后销毁进程。
6. 输出和异常写入 `SubreportTaskLogger`。

`LoadOcacleListener` 实现了 `ServletContextListener`，包含 Timer 定时备份和 SSH/SCP 逻辑，但 `web.xml` 未注册该 listener；按当前配置不会随容器启动自动执行。

## 4. 登录与会话生命周期

真实入口：

- `/main` → `login.jsp`
- `/main/index` → `index.jsp`
- `/main/login` → 执行登录

`LoginController.login` 逻辑：

1. 接收 `user_account`、`encoded_password`。
2. 打印 session id 到 stderr。
3. 如果密码非空，调用 `userService.login(user_account, MD5Util.MD5(encoded_password))`。
4. 如果密码为空，调用 `userService.getByAccount(user_account)`。
5. 用户存在时，检查 `checking_status`：
   - `F`：返回 `用户未审核`。
   - `I`：返回 `用户已停用`。
   - 其他：写入 session 属性 `user`。
6. session 超时时间设置为 `-1`，表示永不过期。
7. 写入 `user_logging`。

`LoginInterceptor` 虽然存在，白名单包含 `/login`、静态资源和 `/main`，但未被注册。当前请求如直接访问业务 URL，Controller 内部若未显式校验 session，框架层不会统一阻断。

## 5. 单次普通请求链路

```text
浏览器/JSP Ajax
  -> Tomcat
  -> CharacterEncodingFilter(UTF-8)
  -> DispatcherServlet(/)
  -> Spring MVC 注解匹配 Controller
  -> 参数绑定到 Bean/普通参数/MultipartFile
  -> Controller 调 Service/DAO/工具类
  -> MyBatis/Redis/SMTP/SSH/Python
  -> 返回 JSP 逻辑视图、JSON、文件流或字符串
```

返回形态包括：

- JSP：如 `return "ngs/previewReportList2"`。
- JSON/对象：标注 `@ResponseBody` 或返回 `Result<T>`。
- 文件流：报告下载、Excel 导出、PDF 预览。
- 布尔值：大量 Ajax 更新接口使用 `true/false` 表示成功失败。

## 6. NGS 报告生命周期

### 6.1 数据进入

NGS 数据入口分散在：

- `driver/driverUploadData`：驱动数据上传页。
- `driver/scanUpload`：远程执行上传扫描。
- `life/ParseFile`：解析文件页。
- `filter/*`：筛选 SnpIndel、CNV、Fusion、Chemical、CR、PD、QC。
- `matchingSite/matchingSite`：位点匹配审核。
- `life/insertAnalysisReport`：生成报告记录。

### 6.2 报告预览

JSP `ngs/iframe.jsp` 将报告预览 iframe 指向：

`geneMarkerVw/getGeneMarker?...`

完整匹配数据由：

`geneMarkerVw/getGeneMarkerData`

完成。该方法读取报告、样本、产品、癌种、位点、化疗、免疫、模块化配置，并把结果放入 `Model`，最终返回 `ngs/previewReportList1` 或 `ngs/previewReportList2`。

### 6.3 报告生成

页面调用：

`ngs/createReport`

`NgsReportController.createReport`：

1. 从 session 取 `User`。
2. 调用 `ngsReportService.createReport(...)`。
3. 再调用 `pyReportService.createReport2(...)`，后者是真正生成新 docx 的主流程。
4. 返回 reportId；异常返回 `-1` 并写 `ReportErrorLogger`。

### 6.4 报告下载/预览/状态

- `ngs/download`：按 `report_id` 下载报告文件。
- `ngs/previewPdf`：读取报告文件路径并向 response 输出预览内容。
- `ngs/getPreviewUrl`：按本机 IP 判断基础 URL，拼接报告文件可访问路径。
- `ngs/updateStatus`：更新报告状态，并调用 `SubReportService.generateSubReport`。
- `ngs/updateComment`、`ngs/getComment`：维护报告备注。

### 6.5 报告发送

`ngs/sendEmail`：

1. 从报告、样本中取收件人、抄送人。
2. 合并客户/录单代码配置邮件。
3. 移除错误邮箱名单。
4. 对特殊邮箱地址执行分支处理。
5. 调用 `EmailUtil.getInstance("mail.properties").sendMail(...)`。
6. 邮件成功后异步更新报告状态和发送人。
7. 调用 `/home/cyc/report_url1.py` 同步报告到小程序/信息化系统。
8. 特定条件下触发小报告 HTTP 生成接口。

## 7. 下线与销毁

Spring 销毁 `subreportConsumer` 时调用 `stop()`，该方法将 `isRunning=false`。但消费者线程使用 `brpop(30, queue)`，最多可能等待 30 秒后退出循环。其他 Controller 中手工创建的 `ExecutorService`、`new Thread` 不受容器统一管理。

## 8. 生命周期风险

- 登录拦截器未启用，session 校验不统一。
- Service 与 Controller 被 root/MVC 容器重复扫描。
- `SubreportConsumer` 为非守护线程，Redis 异常时持续重试。
- `LoadOcacleListener` 有定时备份逻辑但未注册，容易被误认为已生效。
- 多处 Controller 中直接创建线程池或线程，缺少统一关闭、限流和监控。
- `TemplateUtil2` 等待 Python 进程时未并发消费 stdout/stderr，存在输出阻塞风险。
